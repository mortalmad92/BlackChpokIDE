# Агент не виконує завдання: «Модель повернула порожню відповідь»

Дата: 2026-11-12. Звіт про дефекти, знайдені живим прогоном у вікні IDE, і
про виправлення. Кожен пункт має ЗАМІР, а не припущення.

## Що бачив користувач

Скріншот (Ministral-3-14B-Instruct-2512-Q4_K_M, вбудований рушій, власний
комп'ютер):

1. Запит: «Напиши сайт у вигляді блогу і форуму де можна спілкуватися в
   коментарях, з своїм API для підключення агента який буде потім постити
   цікаві новини. Без використання PHP.»
2. Блок «Аналіз запиту» → «Зупинено · 0 кроків · 6 с».
3. Відповідь: **«Модель повернула порожню відповідь.»**
4. На диску — нічого.

Другий запит користувача (скріншот 2): «Взагалі не хоче працювати агент
відповідно до поставленої задачі… не просто перевірка в фоні».

## Причина №1 (головна): модель кликала інструмент у СВОЄМУ форматі

Шаблон чату в GGUF у Mistral/Ministral описує рівно один формат виклику:

```
[AVAILABLE_TOOLS][{…схеми…}][/AVAILABLE_TOOLS]
[TOOL_CALLS]write_file[ARGS]{"path": "a.py", "content": "…"}
[TOOL_RESULTS]Записано a.py[/TOOL_RESULTS]
```

IDE показувала моделі ЛИШЕ свій текстовий протокол українською
(`{"tool": …, "arguments": …}`), а `[TOOL_CALLS]` не розумів **жоден**
розбирач. Замірено: модель слухняно віддавала `[TOOL_CALLS]project_tree[ARGS]{"depth": 2}`,
`llama_client.extract_tool_calls` повертав `[]`, текст вирізався як
службовий — і агент писав «порожня відповідь».

Доказ (сирі токени рушія, `tools/probe_empty_answer.py`):

```
['{"', 'tool', '":', ' "', 'list', '_dir', '"}']   ← відповідь на 200 токенів
```

Модель, отримавши СВІЙ формат, те саме завдання виконує:

```
[TOOL_CALLS]write_file[ARGS]{"path": "blog_forum/requirements.txt", "content": "fastapi\nuvicorn\n…"}
```

**Виправлено:** доданий `blackchpok_ide/tool_dialect.py` — визначає діалект
із Jinja-шаблону моделі (`[TOOL_CALLS]` у Mistral, `<tool_call>` у Qwen) і
вміє і подати опис інструментів цим форматом, і розібрати виклик.

## Причина №2: історія дій не доходила до моделі

`LlamaChatMessage` містить лише `role` і `content` — ні `tools`, ні
`tool_calls` у шаблон не передаються. Замірено, що промпт другого кроку був:

```
[INST] … [/INST] </s> Записано a.txt</s>
```

Тобто модель бачила результат інструмента БЕЗ власного виклику й без
позначки «це результат» — і не мала де почати відповідь
(`add_assistant` у шаблоні Mistral відсутній).

**Виправлено:** `Dialect.render_history()` збирає промпт за шаблоном моделі
сам, з `[TOOL_CALLS]…[/TOOL_RESULTS]` і відкритим ходом асистента. Для Qwen —
ChatML із `<tool_call>` і `<tool_response>`.

## Причина №3: системний промпт у `settings.json` не оновлювався

`settings.json` зберігає **повний текст** системного промпту. Через це
виправлення в `DEFAULT_SYSTEM_PROMPT` **не доходило до користувача взагалі**:
у файлі лежала копія від першого запуску, де мережа названа «ОБОВ'ЯЗКОВИМ
ІНСТРУМЕНТОМ», — і модель на «напиши сайт» ішла в `search_web`.

Замірено на справжніх налаштуваннях користувача: збережений промпт починався
з «Ти — Blackchpok AI» (мала «p») і містив стару фразу.

**Виправлено:** міграція `_is_stock_prompt()` — оновлює лише НАШУ стару
копію, власний текст людини не чіпає. Плюс у самому промпті з'явився пункт 0:
«СПЕРШУ ЗРОБИ ТЕ, ЩО ПРОСЯТЬ, ПОТІМ ШУКАЙ».

## Причина №4: перший порожній хід завершував роботу

Було: `self._error = "Модель повернула порожню відповідь."` і `return`.
Один хід — і діагностика замість файлів.

**Виправлено:** спершу підказки роутера, далі один повтор із прямою вимогою
діяти (`EMPTY_ANSWER_RETRIES`), і лише потім — пояснення, ЩО сталося і що
робити (`_empty_answer_reason`).

## Причина №5: роутер підміняв завдання пошуком

«Напиши сайт … який буде постити цікаві **новини**» містить слово «новини»,
і роутер перетворював ЗАВДАННЯ на `search_web`. Замірено: агент шукав в
інтернеті замість того, щоб створити файли.

**Виправлено:** `_is_build_request()` — якщо у фразі є і дієслово створення,
і назва речі (сайт, бот, застосунок, файл), мережеві слова вважаються ОПИСОМ,
а не запитом пошуку. Питання про ціну/курс/погоду працюють як раніше.

## Причина №6: код у чаті не ставав файлами

Модель писала код блоками ```html``` / ```python``` у ЧАТ, але не кликала
`write_file`. Було лише нагадування — і робота зникала.

**Виправлено:** `_salvage_code_files()` — блок із назвою файлу в заголовку
(```` ```python app/main.py ````) зберігається на диск. Незакритий блок теж
(модель спиняється на обмеженні довжини — саме так зникав головний `app.py`).
Захист: без назви не пишемо, наявний непорожній ф��йл не перезаписуємо,
шляхи з `..`/диском/абсолютні відкидаються.

## Причина №7: обірваний виклик витікав у чат

На скріншоті після обриву посеред аргументів у чаті висіло `let[ARGS]` з
уривком JSON.

**Виправлено:** `strip_native_calls()` і `ToolCallParser.finish()` прибирають
обірваний виклик цілком; маркери `[TOOL_CALLS]`/`[ARGS]`/`[AVAILABLE_TOOLS]`/
`[TOOL_RESULTS]` додані в ознаки службового протоколу.

## Причина №8: `�` у кінці обірваної відповіді

Кирилиця займає два байти; при обриві генерації хвіст лишався неповним і
`errors="replace"` давав `�`. Замірено: «… як моє щастя.** �».

**Виправлено:** `StreamingDecoder._drain()` відкидає обірваний хвіст (до 3
байтів) замість позначення його «заміною».

## Причина №9: модель питала дозволу замість роботи

Після трьох файлів модель писала «Наступні кроки: … Смакуй, як продовжити.»
і зупинялась — а користувач просив сайт, не план.

**Виправлено:** одне продовження (`_continue_asked`) для завдання
«створити», коли текст розпізнано як прохання дозволу
(`_asks_permission_or_next`).

## Як перевірено

* `python -m unittest discover -s tests -p "test_*.py"` — **2307 тестів, 0 збоїв**;
* `tests/test_agent_executes_task.py` — 47 нових тестів на кожну причину;
* `tests/live_gui_executes_task.py` — живий прогін у СПРАВЖНЬОМУ вікні: запит
  у поле чату → кнопка надсилання → перевірка файлів на диску.

Результат живого прогону: створено `app.py`, `news_api.py`, `blog.html`,
`forum.html`, `home.html` — бекенд, API і три сторінки. «Порожньої
відповіді» немає.

## Чого це НЕ робить

* не «вигадує» дії замість моделі: порятунок коду пише лише те, що модель
  сама підписала назвою файлу;
* не чіпає власний системний промпт користувача;
* не забороняє інтернет: питання про ціни, курси, погоду, новини шукаються
  як і раніше.
