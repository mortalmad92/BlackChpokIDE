# Правило «немає доказу — немає твердження»

Дата: 2026-11-09. Реалізовано в `blackchpok_ide/evidence.py` + інтеграція в
`agent.py`.

---

## 1. Правило

**NO TOOL EVIDENCE — NO FACTUAL PROJECT CLAIM.**

Будь-яке твердження про реальний стан проєкту дозволене лише тоді, коли в
цьому ході був **успішний виклик інструмента**, який це твердження
підтверджує.

Під правило підпадають:

* кількість файлів, тестів, функцій;
* імена файлів і структура проєкту;
* вміст файлів;
* наявність функцій і класів;
* стан сервісів (сервер, модель, MCP, порт);
* налаштування;
* результати запуску й тестів.

---

## 2. Чому це потрібно

Конкретний випадок із попереднього аудиту:

```
Запит: «Скільки .py файлів у теці?»
Агент: «Знайдено 1 файл: main.py»      ← call_tool не викликався
Реальність: 100 файлів
```

Користувач не міг відрізнити факт від вигадки: обидва виглядали однаково
впевнено.

---

## 3. Як працює

### 3.1. Класифікація тверджень

`evidence.factual_claims(text)` знаходить речення, які виглядають як факт:

| Шаблон | Приклад |
|---|---|
| кількість + предмет | «37 файлів», «12 тестів» |
| ім'я файлу | «файл server.py містить…» |
| стан проєкту | «у проєкті є…», «тести пройшли» |
| стан сервісів | «сервер запущено на порту 8080» |
| явне «я перевірив» | «я прочитав файл…» |

**Оцінки й поради відсіюються**: «раджу використати кеш» не потребує
доказу з інструмента.

### 3.2. Зіставлення з доказами

`evidence.check(answer, evidence)` перевіряє кожне твердження проти
результатів інструментів: числа, імена файлів, змістовні слова.

### 3.3. Що робить агент

`AgentRunner._enforce_evidence()` на фінальній відповіді:

1. **Усе підтверджено** → відповідь показується як є.
2. **Є докази, але твердження без них** → відповідь **перебудовується з
   реальних результатів** (`_answer_from_tools`), з попередженням зверху.
3. **Доказів немає зовсім** → додається явне попередження:
   «⚠ Ця відповідь не підтверджена даними з проєкту…»
4. **Роботу обрізано лімітом кроків** → додається:
   «⚠ Роботу зупинено лімітом кроків — перевірка не завершена».

### 3.4. Проактивний захист

Навіть якщо класифікатор наміру помилково відніс запит до «розмови»,
`_run()` перевіряє `evidence.needs_tools_for(text)`:

```python
forced_tools = evidence_module.needs_tools_for(text)
if forced_tools and not self.tools_enabled:
    # режим «Чат» — чесна відмова замість вигадки
if self._is_small_talk() and not forced_tools:
    ...
```

Тобто шлях «балачка без інструментів» **не може приховати** доступ до
інструментів для запитів про проєкт.

### 3.5. Виправлені дефекти (аудит 2026-11-09)

| Дефект | Було | Стало |
|---|---|---|
| числа як підрядок | «12 файлів» підтверджувалось доказом «line 120» | числа порівнюються як числа (`\b12\b`) |
| маркери оцінки глушили факти | «Потрібно знати: у проєкті 300 файлів» → не факт | прямий факт перемагає маркер оцінки |
| тихий прохід | факт без жодного виклику → `supported=True` | `supported=False`, якщо в ході 0 успішних викликів |
| зоровий доказ не рахувався | `VISUAL_TOOLS` оголошений, але не перевірявся | скріншот дає `has_project_evidence` |
| порядок умов | `_is_small_talk()` перевірявся ПЕРЕД `forced_tools` | факт перевіряється першим |
| обрізання | лише за номером кроку, `finish_reason` не читався | `finish_reason="length"` + межа кроків включно |
| гілки відповіді | правило діяло в 1 з 5 місць | усі шляхи відповіді проходять `_enforce_evidence` |
| маркери запиту | «спорт-сайт» → «порт», «стандарт» → «стан» | межі слів + «порівняй», «компіл» |

## 4. Перевірено

### Одиничні випадки

```
1) без доказів: supported=False, claims=2
   ⚠ Ця відповідь не підтверджена даними з проєкту…
2) з доказом find_files(100 шляхів): supported=True
3) порада без доказу: supported=True   ← правильно, це не факт
```

### Класифікація запитів

```
«Скільки .py файлів?»        -> потребує інструментів: True
«Привіт»                     -> потребує інструментів: False
«Скільки коштує біткоїн?»    -> потребує інструментів: False (це мережа)
```

### Живий прогін

```
TOOLS CALLED: ['list_dir', 'list_dir']
EVIDENCE: EvidenceCheck(unsupported=[], has_any_success=True,
                        has_project_evidence=True, supported=True)
```

---

## 5. Обмеження (чесно)

* Зіставлення «твердження ↔ доказ» **м'яке**: воно ловить очевидні випадки
  (немає жодного виклику, число не згадується в жодному результаті), але не
  доводить семантичну правильність. Це робота моделі, а не регулярних
  виразів.
* Правило не блокує відповідь — воно додає попередження або перебудовує її
  з реальних даних. Блокування виглядало б як «агент мовчить».
* `needs_tools_for` — евристика; складні формулювання можуть не потрапити
  під неї. Тоді працює основний шлях (класифікатор наміру), який уже
  виправлено.
