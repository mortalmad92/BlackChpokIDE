# Git і GitHub: прив'язка до чату й проєкту

Дата: 2026-11-12. Що зроблено за запитом: «зроби git з прив'язкою до чату і
проєкту з яким працює агент і щоб агент міг запитувати, чи потрібно оновити
файли на github».

## Головне правило

**Агент питає — відправляє людина.** ``git push`` незворотний: коміт одразу
бачать усі, хто має доступ до репозиторію, і локальний ``git reset`` цього не
виправить. Тому:

* питання ставиться ЛИШЕ після успішної роботи, коли агент справді змінив файли;
* без відповіді «так» не робиться нічого — перевірено тестом
  `test_without_confirm_publish_is_not_called`;
* інструмент ``git_publish`` без ``confirm=true`` повертає відмову й
  пояснення, а не мовчки відправляє.

## Прив'язка до чату й проєкту

Git живе в ЧАТІ (`chat_store.Chat`), а не в налаштуваннях програми:

| Поле | Навіщо |
|---|---|
| `git_remote` | адреса, яку агент показав у питанні |
| `git_last_push` | час останньої успішної відправки |
| `git_auto_ask` | питати в цьому чаті чи ні |

Чому так: людина працює в кількох проєктах одночасно, і «на GitHub» у кожного
своя адреса. Спільне поле означало б, що чат проєкту А відправив зміни в
репозиторій проєкту Б. Перевірено: `test_each_chat_keeps_its_own_remote`.

Тека теж береться з чату: `AgentRunner.workspace` — це `chat.workspace`.
`git_repo.state()` кличе `git rev-parse --show-toplevel`, тож якщо тека чату
лежить УСЕРЕДИНІ репозиторію, публікується саме цей репозиторій.

## Як це виглядає для людини

1. Агент попрацював і змінив файли.
2. У чаті з'являється питання з подробицями:
   ```
   Оновити файли на GitHub?
   - репозиторій: https://github.com/user/repo.git
   - гілка: main
   - файли: `app.py`, `style.css`
   - коміт: оновлено app.py, style.css (BlackChpok IDE)
   ```
3. Відкривається діалог «Так / Ні».
4. Можна відповісти й словами в чаті: «так», «запуш», «онови файли».
5. Або зробити це вручну: меню **Git → Оновити файли на GitHub…**

## Безпека

| Ризик | Як закрито |
|---|---|
| Токен у командному рядку | передається через `GIT_ASKPASS` + змінна оточення; аргументи процесу на Windows видно іншим процесам (`test_askpass_env_hides_token_from_argv`) |
| Токен у файлі налаштувань | шифрується DPAPI, як ключі провайдерів; у файлі лише `token_enc` |
| Токен у логах і помилках | `git_repo.redact()` прибирає `https://user:TOKEN@…` і `ghp_…` |
| Коміт із секретами | `.env`, `id_rsa`, `*.pem`, `credentials.json` блокують публікацію |
| Внутрішні теки IDE в коміті | `.agents/`, `.buildtmp/`, `.dsh/` виводяться в `.git/info/exclude` (локально, без правки чужого `.gitignore`) |
| `push --force` | не використовується ніколи |
| Режим «лише читання» | `git_publish` заборонений, а в решті режимів завжди питає |

## Нові інструменти агента

| Інструмент | Що робить | Ризик |
|---|---|---|
| `git_remote_info` | стан репозиторію, адреса origin, перелік змін | читання |
| `git_publish` | коміт + push (**лише** з `confirm=true`) | зовнішній |

`git_remote_info` існує окремо, щоб модель називала СПРАВЖНЮ адресу в питанні,
а не вигадану: вона бере її з `git remote get-url origin`.

## Налаштування

Вкладка **Агент → GitHub**:

* «Питати “оновити файли на GitHub?” після успішної роботи» — типово увімкнено;
* «Токен GitHub» — потрібен лише тоді, коли git не має збережених облікових
  даних (Git Credential Manager). Достатньо доступу `repo`.

## Як перевірено

```
python -m unittest tests.test_git_publish        # 36 тестів на справжньому git
python tests/live_git_offer.py                   # живий цикл: питання → згода → push
python tests/live_git_ui.py                      # вікно: меню, діалог, «Так»/«Ні»
```

`tests/live_git_offer.py` іде тим самим шляхом, що й GUI, а замість GitHub
використовує локальний bare-репозиторій: та сама семантика `push`, без мережі.

Результат живого прогону:

```
[OK] агент спитав про GitHub — 1 подій
     питання: Оновити файли на GitHub? Змін: 1 · …\origin.git · гілка main
[OK] на GitHub ще немає нового коміту — 580b513 початок
[OK] агент зрозумів «так»
[OK] на GitHub з'явився новий коміт — f5d7ab1 оновлено app.py (BlackChpok IDE)
```

Результат у вікні (справжній `BlackChpokIDE`):

```
[OK] у діалозі є адреса / гілка / файл
[OK] зміни дійшли до репозиторію — 7f17ed8 оновлено app.py (BlackChpok IDE)
[OK] після «Ні» нічого не поїхало — комітів було 2, стало 2
```

## Чого це НЕ робить

* не створює репозиторій на GitHub (для цього потрібен свій токен і
  `gh`/API; зараз `origin` має вже існувати);
* не робить `pull` і не вирішує конфлікти — при «remote went ahead» агент
  каже причину й пропонує `git pull`, а не `--force`;
* не чіпає налаштування git користувача (`user.name`, `user.email`).
