# Можливості моделей і значки в Model Hub

Дата: 2026-11-09.

---

## 1. Правило, яке тепер діє

**Значок означає перевірений факт, а не слово в назві файлу.**

| Значок | Значення | Коли ставиться |
|---|---|---|
| 🔨 | виклик інструментів | родина моделі це підтримує |
| 🧠 | окрема reasoning-версія | є ознака `reasoning`/`reasoner`/`magistral` |
| 🖼 | читає зображення | є **файл `mmproj` на диску**, сумісний із цією моделлю |
| 🎙 | робота з голосом | ознака `whisper`/`audio`/`voxtral` |

---

## 2. Що було зламано

`model_caps.detect()` визначав зір **лише за назвою**:

```python
VISION_MARKERS = ("vision", "-vl", "vl-", "llava", "pixtral", ...)
```

Два наслідки:

1. **Хибно-позитивні.** Модель із `-vl` у назві отримувала зелений 🖼,
   навіть якщо поруч **не було** `mmproj`. llama.cpp стартував без
   `--mmproj`, `vision_enabled` ставав `False`, і знімки тихо не передавались.
   Користувач бачив значок зору й не розумів, чому модель «не бачить».
2. **Хибно-негативні.** `Ministral-3-14B-Instruct` — мультимодальна модель
   (safetensors, `mistral3` на Hugging Face), але в назві немає `vl`/`vision`,
   тому значка не було взагалі.

---

## 3. Як перевіряється тепер

`detect(..., local_path=...)` для вже завантаженого GGUF робить **фактичну**
перевірку:

```python
projector = model_hub.vision_projector_for(path)
if projector is None:
    caps.flags[VISION] = False        # знімаємо значок
else:
    caps.set(VISION, True, f"проєктор {projector.name}")
```

### Перевірено на реальних файлах

```
mmproj-Qwen3VL-8B-Instruct-F16.gguf       icons=🔨 🖼   (це сам проєктор)
qwen2.5-coder-14b-instruct-q4_k_m.gguf    icons=🔨        ← текстовa, зору немає
Qwen2.5-VL-3B-Instruct-Q4_K_M.gguf        icons=🔨 🖼   проєктор: mmproj-Qwen2.5-VL-3B…
Qwen3VL-8B-Instruct-Q4_K_M.gguf           icons=🔨 🖼   проєктор: mmproj-Qwen3VL-8B…
```

Текстова 14B коректно **не** отримує значок зору.

---

## 4. Сумісність проєктора

`model_hub.vision_projector_for()` шукає `*mmproj*.gguf` у тій самій теці й
перевіряє, що він стосується тієї самої родини (марка + розмір):

* `Qwen2.5-VL-3B-Instruct` ↔ `mmproj-Qwen2.5-VL-3B-Instruct-f16` — **так**;
* `qwen2.5-coder-14b` ↔ будь-який `mmproj` — **ні** (падало б на несумісності).

Список мультимодальних родин розширено, щоб Ministral теж міг отримати
проєктор: `ministral`, `mistral-3`, `mistral3`, `pixtral`, `magistral`,
`gemma-3`. Якщо файлу `mmproj` немає — зору не буде й значка не буде, що чесно.

---

## 5. Ручне виправлення

`from_hit()` спершу рахує автоматично, потім накладає збережене
`capabilities` із запису моделі. Тобто ручна правка користувача має вищий
пріоритет за вгадування — людина могла перевірити модель на практиці.

---

## 6. Каталог моделей

`hardware.MODEL_CATALOG` — 7 моделей від 0.5B до 32B, кожна з:

* репозиторієм і файлом;
* приблизним розміром;
* мінімальною пам'яттю;
* кількістю шарів (для розрахунку часткового offload).

Для кожної рахується `hardware.fit()`: влізе повністю на GPU, гібридно чи
лише на CPU.

## 7. Кнопка «Перевірити можливості»

У хабі моделей є кнопка, яка виконує **справжні** запити до запущеного
сервера й показує доказ кожного результату: `model_verify.run_all()`.

| Тест | Що саме перевіряється | Доказ |
|---|---|---|
| `tool_calling` | модель викликає інструмент і повертає структурований `tool_call` | ім'я функції + аргументи |
| `vision` | описує **саме це** зображення | згадка очікуваного слова |
| `reasoning` | задача з однозначною відповіддю (3+4−2) | відповідь містить **окреме** число 5 |
| `json_output` | віддає валідний JSON | розібраний об'єкт |
| `streaming` | текст приходить частинами | кількість SSE-пакетів + текст |
| `context` | приймає довгий запит **і відповідає по суті** | назване число повторів |
| `cuda` | GPU доступний і бекенд встановлений | назва GPU, VRAM, бекенд |

### Виправлені фальшиві «зелені»

| Було | Чому це неправда | Стало |
|---|---|---|
| `vision`: `expected=()` → `PASSED` | будь-яка відповідь, навіть «не можу аналізувати зображення» | без еталона тест **не проходить**; GUI передає еталон |
| `reasoning`: `"5" in text` | «25 яблук» проходило | число мусить стояти окремо |
| `context`: `PASSED if text` | «не знаю» проходило | відповідь мусить назвати правильне число |
| `streaming`: лише лічильник пакетів | пакети могли бути порожні | збирається й перевіряється текст |
| `cuda`: тесту не було | значок CUDA означав «у назві є cuda» | окремий тест заліза й бекенду |
| результати жили в пам'яті | після перезапуску доказів немає | `capabilities_verified.json` |

### Чесні значки в списку моделей

До натискання кнопки значки з назви файлу показуються з префіксом **`?`** —
це припущення, а не доказ. Після перевірки показується результат тесту.

---

## 8. Чого ще немає (чесно)

* Перевірка CUDA не робить реального завантаження шарів на GPU: вона
  дивиться на залізо й наявність бекенду. Справжній offload перевіряється
  запуском моделі.
* Немає фільтрів у хабі («підтримує інструменти», «підтримує зображення»).
