# BlackChpok AI — локальний MCP-сервер для вайб-кодингу

Сервер `server.py` (версія 9.1) — це один MCP-інструмент `master_agent_router`. Користувач пише звичайною українською і не називає інструментів. Модель передає текст як є (`intent=auto`, `request` = дослівне прохання), а сервер сам обирає дію і виконує її в папці `MCP_WORKSPACE`.

Окремі імена на кшталт `read_file` чи `rag_search` існують усередині сервера. Модель їх не перелічує і не вигадує нових: Kubernetes, Prometheus, сканери мережі та хмарні панелі в цей набір не входять.

## Що вміє агент

- **Огляд:** папки, карта проєкту, стек, аналіз репозиторію, схема SQLite, локальний перегляд сторінки лише на `127.0.0.1` / `localhost`.
- **Код:** читання, пошук тексту і символів, індекс функцій, статична перевірка свого коду, запис із копією `.bak` і відкат останньої правки.
- **Збірка:** кілька файлів за розміткою `### FILE:`, запуск і ремонт Python-скрипта.
- **Термінал:** версії, `where`, `pip` у `.venv`, `npm`, `winget`. Українську фразу сервер перетворює на одну команду Windows, а не віддає її в `cmd` як є.
- **Git:** status, diff, log, show.
- **Пам'ять:** правила, нотатки проєкту, історія чату, RAG по файлах (SQLite FTS5 і, якщо є endpoint, вектори).
- **Мережа:** Wikipedia, DuckDuckGo, погода Open-Meteo, курс Frankfurter, короткий фінансовий огляд CoinGecko і Google News. Це не порада купувати.
- **Соцмережі:** чернетка посту. Публікація лише якщо в фразі є «опублікуй» / «виклади» / «запости», названа мережа і задані токени офіційного API (X, Facebook, Telegram, Mastodon).

## Встановлення сервера

1. Папка має лишатися на місці, наприклад `C:\AI\blackchpock_ai`.
2. Python 3.11 або новіший. На цій машині сервер іде з `.venv` (зараз Python 3.14).
3. Запустіть `install.bat`. Він створить `.venv` і поставить залежності.
4. `MCP_WORKSPACE` — папка проєкту, з яким працює агент, не корінь диска.
5. Після зміни `server.py` перезапустіть MCP-сервер у своєму клієнті й почніть новий чат. Старий процес stdio тримає старий код.

Перевірка RAG без клієнта:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Запуск `python server.py` у консолі лише чекає MCP у stdin. Це нормально, так його підключає MCP-клієнт.

## Налаштування MCP-клієнта

MCP-клієнт і вікно LM Studio — різні програми. Чат агента живе в клієнті. Модель і embeddings піднімає локальний сервер LM Studio.

### 1. Модель

Потрібна модель із підтримкою інструментів. На цій машині це **Ministral 3 14B Reasoning**, квантизація Q4_K_M, ідентифікатор API `ministral-3-14b-reasoning`. У картці моделі має бути позначка інструментів (молоток).

Файл параметрів:

`C:\Users\Admin\.lmstudio\hub\models\mistralai\ministral-3-14b-reasoning\model.yaml`

Робочі значення для Ryzen 5 3600, 64 ГБ RAM і RTX 3060 12 ГБ:

| Параметр | Значення |
| --- | --- |
| Контекст | 16384 |
| GPU offload | 100% |
| KV-кеш | q8_0, не fp16 |
| Потоки CPU | 6 |
| Eval batch | 512 |
| Temperature | 0.4 |
| Бюджет міркування | 128 токенів |
| Вибір інструмента | `auto` |

Бюджет міркування лишайте низьким. На 2048 токенах Ministral встигає написати анкету і не викликає інструмент. Режим `required` не використовуйте: модель починає викликати інструмент по колу і повторює інструкцію замість файлів.

Після правки `model.yaml` модель треба вивантажити і завантажити знову. Вже відкритий чат старі параметри не підхоплює.

Локальний API на цій машині: `http://127.0.0.1:1235/v1`. Порт має збігатися з `MCP_LMSTUDIO_URL`.

Окремо завантажте embedding-модель `nomic-embed-text-v1.5` (у API: `text-embedding-nomic-embed-text-v1.5`), інакше пам'ять лишається лише повнотекстовою.

### 2. Підключення сервера MCP

Сервер називається **blackchpok-ai**, тип `stdio`, таймаут 300000 мс. Команда — Python із `.venv`, аргумент — `server.py`, робоча тека — папка репозиторію.

Приклад конфігу для MCP-клієнта:

```json
{
  "servers": [
    {
      "name": "blackchpok-ai",
      "enabled": true,
      "connection": {
        "type": "stdio",
        "command": "C:\\AI\\blackchpock_ai\\.venv\\Scripts\\python.exe",
        "args": ["C:\\AI\\blackchpock_ai\\server.py"],
        "cwd": "C:\\AI\\blackchpock_ai",
        "env": {
          "MCP_WORKSPACE": "C:\\AI\\blackchpock_ai",
          "MCP_LLM_BACKEND": "auto",
          "MCP_LMSTUDIO_URL": "http://127.0.0.1:1235/v1",
          "MCP_LMSTUDIO_MODEL": "ministral-3-14b-reasoning",
          "MCP_LMSTUDIO_API_KEY": "lm-studio",
          "MCP_DB_PATH": "C:\\AI\\blackchpock_ai\\.mcp_rag\\memoria_infinita.db",
          "MCP_RAG_EMBEDDINGS_URL": "http://127.0.0.1:1235/v1/embeddings",
          "MCP_RAG_EMBEDDINGS_MODEL": "text-embedding-nomic-embed-text-v1.5"
        },
        "timeoutMs": 300000
      }
    }
  ]
}
```

У JSON шляхи Windows пишуться з подвоєними `\\`. Не підставляйте `run_server.bat` у `command`.

У клієнті сервер має бути увімкнений. Якщо після правки `server.py` відповіді старі, вимкніть MCP і увімкніть знову.

`run_server.bat` лишається для ручного запуску в консолі, не для MCP-клієнта.

### 3. Тип чату

Новий чат створюйте в режимі з повним набором інструментів. У такій сесії підключені файли проєкту, термінал, MCP, Python і пошук.

Не використовуйте сесію, у якої в конфігурації стоїть модуль `lmstudio/disable-tool-calls-v1` і `readOnly: true`. У такому чаті моделі фізично немає інструментів, і вона чесно пише, що не бачить код.

Підказка `@C:\AI\blackchpock_ai` уже дає читання цієї папки. Якщо модель пише «немає доступу», вона проігнорувала підказку, а не отримала заборону.

Підтвердження кожного інструмента краще вимкнути (`neverAskForToolConfirmation: true` у налаштуваннях клієнта), щоб виклик не чекав на вікно. Субагенти-дослідники теж варто вимкнути (`explorationSubagentEnabled: false`): вони паралельно «досліджують» проєкт і не віддають список файлів у відповідь.

Мова інтерфейсу клієнта (`language: uk`) міняє лише меню. Мову відповіді моделі вона не задає.

### 4. Наказ працювати інструментами

Чат на старті копіює системний промпт із конфігурації програми. Окремі файли на кшталт `System_Prompt.md` чи `config.yaml` у цей промпт не підставляються. Правити треба сам рядок промпту. Зараз на його початку стоїть наказ:

1. Прохання про файли, проєкт, аналіз, пошук або зміну починається з виклику інструмента. Текст до результату заборонений.
2. Шлях у повідомленні вже можна читати. Не писати, що доступу немає.
3. Користуватися підключеними інструментами. Не вигадувати інструменти, яких немає в результаті.
4. Після одного результату відповісти українською. Той самий виклик не повторювати.

Поки клієнт відкритий, у пам'яті старий промпт. Після правки повністю закрийте програму, включно з іконкою в треї, і відкрийте знову. Далі лише новий чат.

Оновлення клієнта перезаписує файл промпту і стирає цей наказ. Після оновлення його треба повернути.

Додатково той самий зміст лежить у скілі `ukrainian-reply`. Клієнт додає опис скіла в запит. Скіл проєкту, який завжди увімкнений:

`C:\Users\Admin\.lmstudio\apps\projects\d49037d8-47f4-5808-9028-c707de117f8f\workspace\.agents\skills\ukrainian-reply\SKILL.md`

Копія для всіх проєктів: `C:\Users\Admin\.lmstudio\skills\ukrainian-reply\SKILL.md`. Глобальний скіл ще треба увімкнути в налаштуваннях клієнта, розділ Skills. Скіл у папці `.agents\skills` поточного проєкту вмикати окремо не треба.

Мова відповіді продубльована в шаблоні Ministral (`llm.load.promptTemplate` у `model.yaml`): після системного промпту стоїть рядок відповісти українською за результатом інструмента і не повторювати виклик. Шаблон теж читається лише під час завантаження моделі.

### 5. Перевірка, що налаштування живе

1. Локальний сервер LM Studio відповідає на `http://127.0.0.1:1235/v1`, модель завантажена.
2. MCP-сервер «blackchpok-ai» у клієнті увімкнений.
3. Клієнт повністю перезапущений після правки промпту.
4. Новий чат з інструментами, модель Ministral 3 14B Reasoning.
5. Запит: `@C:\AI\blackchpock_ai проаналізуй проект`.

Очікувана відповідь: один виклик інструмента, потім українською реальні файли (`server.py`, `agent_tools.py`, `vibe_router.py`, `rag_engine.py`, `tests`). Анкета про стек, хмару і кількість людей означає, що інструмент не викликано. Три однакові виклики поспіль означають, що знову ввімкнено примусовий `toolChoice: required`.

Фраза для індексу пам'яті: «проіндексуй проєкт».

## Пам'ять і RAG

База індексу: `.mcp_rag\index.sqlite3`. База агента: `.mcp_rag\memoria_infinita.db` (правила, чат, символи коду, нотатки проєкту).

Без embeddings працює FTS5/BM25. З `MCP_RAG_EMBEDDINGS_URL` на `127.0.0.1` пошук гібридний. Якщо endpoint мовчить, сервер кілька разів пробує знову, а не вимикає вектори назавжди. Після зміни текстів варто переіндексувати. Секрети (`.env`, ключі) в індекс не беруться.

Індекс символів обходить `.py`, `.js`, `.ts`, `.tsx`, `.jsx`, пропускає `.venv` і файли більші за 400 КБ.

## Межі

- Файлові дії обмежені `MCP_WORKSPACE`. `.git` не видаляється.
- Запис існуючого файлу кладе копію `.bak`. «Відкоти останню правку» повертає її.
- Видалення, розпакування ZIP і завершення процесу вимагають підтвердження.
- Фільтр shell не є пісочницею: команда йде з правами вашого користувача Windows. `MCP_ALLOW_DANGEROUS_COMMANDS=1` не вмикайте без потреби.
- Сервер не піднімає прав адміністратора, не керує мишею і клавіатурою, не вимикає ПК і не обходить обмеження моделі.
- Перевірка коду статична і лише для ваших файлів. Сканування чужих сайтів і програм сервер не робить.
- Чернетка соцмережі не публікується, поки ви самі не скажете опублікувати і не вкажете мережу. Токени: `MCP_X_ACCESS_TOKEN`, `MCP_FACEBOOK_PAGE_ID` і `MCP_FACEBOOK_PAGE_TOKEN`, `MCP_TELEGRAM_BOT_TOKEN` і `MCP_TELEGRAM_CHAT_ID`, `MCP_MASTODON_BASE_URL` і `MCP_MASTODON_TOKEN`.
- Сервер працює через stdio і сам порт не відкриває.

## Якщо не підключається

1. `command` і `args` ведуть до наявних `python.exe` і `server.py`.
2. Залежності стоять у тому `.venv`, який вказаний у `command`.
3. `MCP_WORKSPACE` існує.
4. У логах MCP немає помилки імпорту. Сервер пише логи в stderr, stdout зайнятий протоколом.
5. Чат саме Omni, модель із молотком, міркування коротке.
6. Темп-каталог чату існує: `C:\Users\Admin\.lmstudio\.internal\temp`. Без нього клієнт падає на `mkdtemp`.
