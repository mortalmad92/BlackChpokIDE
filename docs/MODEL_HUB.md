# Model Hub

Дата: 2026-11-09.

---

## 1. Призначення

Одне місце, де користувач бачить: які моделі є, що вони вміють, чи
встановлені, чи сумісні із залізом, і кнопку запуску.

Модулі: `model_hub.py` (логіка), `model_hub_panel.py` (інтерфейс),
`model_caps.py` (можливості), `hardware.py` (сумісність).

---

## 2. Значки можливостей

| Значок | Значення | Джерело істини |
|---|---|---|
| 🔨 | виклик інструментів | родина моделі / тег репозиторію |
| 🧠 | окрема reasoning-версія | ознака в назві (`reasoning`, `magistral`) |
| 🖼 | читає зображення | **наявність файлу `mmproj` на диску** |
| 🎙 | працює з голосом | ознака в назві (`whisper`, `audio`) |

Правило: **значок = перевірений факт**. Для зору перевірка — реальний файл
проєктора, а не слово в назві (див. `MODEL_CAPABILITIES.md`).

---

## 3. Завантаження

`model_hub.Download` — фоновий потік із прогресом, докачкою й скасуванням.
Підтримує:

* посилання на репозиторій (`https://huggingface.co/owner/repo`);
* конкретний файл;
* автоматичний вибір квантування (`pick_best_gguf`: перевага `q4_k_m`);
* окреме завантаження `mmproj` для мультимодальних моделей.

Файли `mmproj` **не вважаються моделями** (`is_gguf` їх відфільтровує), бо
сам проєктор моделлю не є.

---

## 4. Підбір під залізо

`hardware.recommend(profile)` обирає найрозумнішу модель, що працює з
прийнятною швидкістю:

1. повністю на GPU — краще за все;
2. частково на GPU (гібрид) — прийнятно;
3. лише CPU — з обмеженням розміру (1–2 токени/с на великій моделі марні).

Для 12 ГБ VRAM рекомендація — Qwen2.5-Coder 14B з `q8_0` KV-кешем.

---

## 5. Запуск

Кнопка «Запустити» викликає `runtime.launch_with_recovery`, який:

* підбирає план за залізом;
* приєднує `mmproj`, якщо він є;
* перевіряє готовність запитом до `/v1/models`;
* після збою GPU **сам повторює** запуск із меншим контекстом або без GPU.

---

## 6. Чого немає

| Можливість | Стан |
|---|---|
| кнопка «Перевірити можливості» (end-to-end тест) | немає |
| фільтри «підтримує інструменти / зображення / все для агента» | немає |
| збереження `testedAt` і доказів тесту | немає |
| показ прогнозу VRAM на картці | частково (план запуску) |
| перемикання Instruct/Reasoning як окремих профілів | через вибір файлу |
| видалення моделі з диска з підтвердженням | немає |

Моделі Instruct і Reasoning — це **різні checkpoint**, тому вони й
завантажуються окремими файлами. Змішувати їх в один профіль не можна.
