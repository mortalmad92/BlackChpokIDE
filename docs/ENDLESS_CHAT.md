# Нескінченний чат: контракт незмінних гарантій

**Дата:** 21.11.2026
**Статус:** обов'язковий контракт. Порушення = регрес, а не «спрощення».

Цей документ існує тому, що попередні агенти вже вирізали ці механізми
«за компанію» з рефакторингом: хардкод-привітання підміняло відповідь
моделі, режим «Чат» забороняв інструменти, а стиснення історії просто
викидало повідомлення. Кожен пункт нижче — **вимога користувача**, а не
деталь реалізації.

> **Правило для будь-якого агента, що читає це.** Перш ніж змінювати
> `agent.py`, `chat_panel.py`, `context_probe.py`, `tool_select.py`,
> `memory_bridge.py` або `longchat.py` — знайди в таблиці §7 пункт, який
> стосується твоєї правки, і переконайся, що тест із §6 усе ще зелений.
> Не розумієш, навіщо код — не видаляй його: спитай.

---

## 1. Головна мета

Чат має працювати **безкінечно** — і на локальній моделі з вікном 8 192,
і на хмарній з вікном 1 000 000 токенів. Модель не повинна впиратись у
«контекст переповнено»: зайве переїжджає в довгострокову пам'ять і
повертається звідти пошуком.

Формула, яку реалізує код:

```
вікно заповнилось (>85% бюджету історії)
        ↓
найдавніші повідомлення ВИТІСНЯЮТЬСЯ
        ↓
        ├── хроніка (longchat)        — зв'язний слід розмови
        ├── NEUROMESH (memory_bridge) — факти й уроки, пошук за змістом
        └── RAG (rag_archive)         — ширший текст із індексом
        ↓
вікно ЗВІЛЬНЕНО → наступні дії
        ↓
модель дістає потрібне через memory_search / rag_search
```

## 2. Гаряче додавання завдань (гаряча черга)

**Вимога:** «гаряче додавання завдань в чат на льоту як для хмарних, так і
локальних моделей».

| Що | Де | Поведінка |
| --- | --- | --- |
| Запит під час роботи агента | `ChatPanel._send` → `_queue_hot` | **не відхиляється**, а стає в чергу |
| Показ прийнятого запиту | `_queue_hot` | картка в стрічці ОДРАЗУ («прийнято») |
| Старт після ходу | `_handle_event` (`done`) → `_run_hot_next` | наступний запит іде сам |
| Межа черги | `chat_panel.HOT_QUEUE_LIMIT` (8) | захист від випадкових Enter |

**Заборонено:** повертати повідомлення «Зачекай: агент ще виконує
попередній запит» замість черги. Саме воно губило набраний текст.

## 3. Автоочищення контексту з перенесенням у пам'ять

**Вимога:** «автоочищення контексту… очищаєш контекст шляхом перенесення
в довгострокову пам'ять і вивільняєш для наступних дій, так до
безкінечності».

| Що | Де |
| --- | --- |
| Перевірка перед КОЖНИМ запитом | `AgentRunner.auto_free_context`, виклик у циклі ходу |
| Поріг спрацювання | 85% бюджету історії (`threshold=0.85`) |
| Витіснення | `AgentRunner._evict_oldest_for_compact(share=0.5)` |
| Перенесення | `AgentRunner._archive_evicted_context` |
| Ручне стиснення `/стиснути` | `AgentRunner.compact` — **теж зберігає** |

**Заборонено:** викидати повідомлення з історії без виклику
`_archive_evicted_context`. Це втрата знань, а не економія: саме через це
довгі сесії «забували», що було вирішено.

**Приватний режим** (`state.private`) — єдиний виняток: вікно
звільняється, але в пам'ять **не пишеться нічого**.

---

## 4. Три сховища — три різні ролі

Не можна замінити одне одним: вони зберігають різне.

| Сховище | Що зберігає | Як повертається |
| --- | --- | --- |
| **Хроніка** (`longchat.ConversationDigest`) | стислий слід розмови, зв'язність | додається в КОЖЕН запит (`_render_digest`) |
| **NEUROMESH** (`memory_bridge`) | факти, обмеження, **уроки з помилок** | `memory_search`, `_lesson_hints` |
| **RAG** (`rag_archive` → `rag_memory`) | ширший текст реплік із індексом | `rag_search` |

Порядок виклику в `_archive_evicted_context`: хроніка → NEUROMESH → RAG.
Помилка будь-якого етапу не ламає хід агента.

---

## 5. Самонавчання через пам'ять

**Вимога:** «реальне самонавчання через довгострокову пам'ять RAG та
NEUROMESH».

| Крок | Де |
| --- | --- |
| Підкласти минулі уроки ПЕРЕД дією | `AgentRunner._lesson_hints_for` → `selflearning.hints` |
| Зробити висновок із ходу | `AgentRunner._learn_from_turn` → `selflearning.learn_turn` |
| Де живуть уроки | NEUROMESH, тип `lesson` |

Уроки **видимі й редаговані** в панелі пам'яті. Це принципово: навчання,
яке не можна переглянути, — не навчання, а непередбачуваність.

Що НЕ стає уроком: випадковий таймаут мережі, разова невдача, виправлена
наступним кроком, будь-що з приватного режиму, вміст файлів.

## 6. Автовизначення вікна контексту

**Вимога:** «автоматичне визначення довжини контексту під будь-яку модель,
жодних обмежень як для локальних, так і для хмарних моделей».

Порядок джерел (від найнадійнішого):

| № | Джерело | Для кого |
| --- | --- | --- |
| 1 | `/props` → `n_ctx` | локальний llama-server (знає про поділ на слоти) |
| 2 | контекст у пам'яті (`native.context`) | вбудований рушій |
| 3 | метадані `.gguf` | локальний файл |
| 4 | **жива проба сервера** (`context_probe`) | **будь-яка** модель, зокрема хмара |
| 5 | каталог провайдера (`cloud_agents`) | відомі хмари |
| 6 | обережний запас | коли нічого не відомо |

**Жива проба** — це те, що робить «під будь-яку модель» правдою:

1. `GET /models` — багато провайдерів віддають `context_length`;
2. пробний запит із `max_tokens` більше за будь-яке вікно — провайдер
   відповідає 400 і **називає ліміт** у тексті;
3. якщо числа немає (так робить справжній Deploy) — **бінарний пошук**
   ліміту пробними запитами.

**Обов'язково: проба йде у ФОНОВОМУ потоці.** Заміряно: бінарний пошук на
живому Deploy — 8 запитів, 55 секунд. Блокувати відповідь не можна: поки
проба працює, беруться каталог і попереднє значення (0.5 с).

**Заборонено:** повертати дві різні стелі `max_tokens` для локальних і
хмарних. Обидві були вигадані нами (32 000 і 200 000) й обидві зрізали
можливості. Лишається лише санітарна межа `MAX_TOKENS_LIMIT`.

## 7. Авто-роутер інструментів

**Вимога:** «щоб не брало всі інструменти без необхідності, а тільки
необхідні при виконанні задачі».

`tool_select.select_names` звужує набір за наміром задачі:

| Профіль | Коли | Приклад набору |
| --- | --- | --- |
| `converse` | розмова, привітання | лише ядро + контроль |
| `inspect` | огляд, «покажи» | читання, пошук, дерево |
| `edit` | «виправ», «зміни» | запис, правка, перевірка |
| `create` | «створи», «напиши» | запис, тека, перевірка |
| `run` | «запусти» | команда, перевірка |
| `research` | «знайди», «пошукай» | пошук, файли |
| `debug` | «не працює», «падає» | запуск, правка, пошук |

Замірено на реальному реєстрі: **56 схем → 6** для «привіт», 8 для
«запусти тести».

**Гарантія досяжності.** `find_tools`, `load_tools`, `run_tool`
показуються **завжди**: будь-який інструмент доступний за один крок,
навіть якщо його схеми немає в запиті. Без цього «економія» стала б
забороною.

## 8. Що заборонено робити (регреси, які вже траплялись)

| Регрес | Наслідок | Захист |
| --- | --- | --- |
| Готовий рядок замість відповіді моделі («Привіт! Готовий допомогти…») | користувач бачив наш текст як відповідь моделі | `test_model_freedom` |
| Режим «Чат» із `use_tools=False` + промпт-заборона | агент вигадував опис проєкту замість читання файлів | `test_model_freedom` |
| Згортання історії без архівування | довгі сесії «забували» вирішене | `test_endless_chat` |
| Відхилення запиту під час роботи | набраний текст губився | `test_endless_chat` |
| Дві стелі `max_tokens` | локальна модель різалась до 32 000 | `test_context_probe` |
| Проба вікна в головному потоці | 55 с очікування перед відповіддю | `test_context_probe` |
| Модель без зору для мультимодальної хмари | картинки не прикріплювались | `test_image_attachments` |

```powershell

python -m unittest tests.test_context_probe -v      # автовизначення вікна
python -m unittest tests.test_model_freedom -v      # свобода моделі
python -m unittest tests.test_image_attachments -v  # зір і іконки
```

Усі чотири набори мусять бути зеленими. Якщо падає — виправ **причину в
коді**, а не тест: ці тести описують вимоги користувача.
