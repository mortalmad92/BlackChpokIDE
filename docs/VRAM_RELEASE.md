# Звільнення відеопам'яті

Дата: 2026-11-09. Виправлено на скаргу користувача: «при закритті програми
треба зробити щоб закривався фоновий процес моделі, щоб я спокійно міг
запускати свої ігри, бо бачу щось грузить відеокарту».

---

## 1. Скільки пам'яті це питання

Виміряно на цій машині (RTX 3060 12 ГБ), модель Ministral 3 14B Q4_K_M:

| Стан | VRAM зайнято |
|---|---|
| До запуску IDE | 768 МіБ |
| Модель завантажена | **9 458 МіБ** |
| Після меню «Вивантажити модель» | 1 020 МіБ |
| Після закриття вікна | 1 012 МіБ |

Тобто модель тримає **близько 8.5 ГБ** — для гри цього достатньо, щоб вона
не запустилась.

## 2. Що було зламано

Сама зупинка працювала: `LocalServer.stop()` коректно вбивав процес. Але
вона **не завжди викликалась**:

1. **Крихке місце в `on_close`.** Виклик `server.stop()` стояв у самому кінці,
   після ~40 блоків `try` (збереження чатів, черги, автономного режиму,
   браузера, терміналу…). Будь-який достроковий `return` — зокрема
   `if not self.tabs.close_all(): return`, коли є незбережені файли — або
   виняток вище лишав процес живим.
2. **Немає обліку PID.** Після аварійного завершення (збій, диспетчер задач,
   закрите вікно консолі) наступний запуск IDE не знав про «сироту».
3. **Немає `atexit`-хука.** При падінні Python `on_close` не виконується
   взагалі.
4. **Порт міг бути зайнятий.** Порт 8080 на цій машині тримає **Steam**
   (`steamwebhelper.exe`), а 8090 — **TorrServer**. `llama-server` падав із
   `couldn't bind HTTP server socket`, тобто сервер не стартував зовсім.

## 3. Що зроблено

### 3.1. Звільнення VRAM — першим ділом

`main_window.on_close` тепер викликає `self._release_model_now()`
**до** збереження стану:

```python
if not self.tabs.close_all():
    return
self._release_model_now()       # ← відеокарта вільна, навіть якщо далі впаде
save_session(...)
```

`_release_model_now()` ідемпотентний і зупиняє **всі** рушії:

1. керований `llama-server` (`_managed_server`);
2. сервер із панелі хаба (`model_hub.server`);
3. власний вбудований рушій (`native_runtime.shut_down()`);
4. залишкові процеси з файлу PID.

### 3.2. Облік PID

`runtime.remember_process()` / `forget_process()` пишуть
`userdata/runtime/managed-servers.json`:

```json
[{"pid": 424, "model": "…Ministral…gguf", "port": 8092, "started": 1794222341}]
```

`cleanup_stale_processes()` прибирає живі рушії з цього списку.

**Безпека.** Зупиняємо ЛИШЕ ті PID, які записали самі, і лише якщо
`tasklist` підтверджує, що це справді `llama-server.exe`. PID після
перезавантаження може дістатись іншій програмі — вбивати її не можна.

### 3.3. Аварійний хук

```python
atexit.register(self._release_model_now)
```

Спрацьовує при звичайному завершенні процесу Python і при `sys.exit`.

### 3.4. Прибирання на старті

У `_startup` запускається фоновий потік `_cleanup_orphans_quietly()`, який
прибирає «сиріт» від попереднього запуску. Якщо щось прибрано, у статусі
з'являється «Звільнено відеопам'ять: зупинено залишкових рушіїв — N».

### 3.5. Ручна кнопка

Меню → Модель → **«Звільнити відеопам'ять (прибрати залишкові рушії)»**
(`agent.free_vram`). Корисна, якщо потрібно звільнити карту негайно, не
закриваючи IDE.

## 5. Порт: окремий дефект, знайдений під час перевірки

`port_is_busy()` перевіряє порт **з'єднанням**, а не лише `bind`: на Windows
`bind` із `SO_REUSEADDR` проходить навіть коли порт уже слухають.

`free_port()` тепер пропускає зайняті порти, а `LocalServer.start()` сам
переводить конфіг на вільний:

```
запрошений порт: 8090 | зайнятий: True (TorrServer)
фактичний порт після start: 8091
READY: True | URL: http://127.0.0.1:8091/v1
INFERENCE: ОК!
```

## 6. Що робити користувачу

1. **Звичайно:** просто закрити IDE хрестиком — модель зупиниться сама.
2. **Якщо гра не запускається:** меню → Модель → «Звільнити відеопам'ять».
3. **Якщо IDE колись впала:** достатньо запустити IDE знову — залишки
   приберуться автоматично.

Перевірити фактично можна так:

```powershell
nvidia-smi --query-gpu=memory.used --format=csv
```

---

## 7. Обмеження

* `atexit` **не** виконується, якщо процес убито примусово
  (`taskkill /F`, збій живлення). Саме для цього є прибирання на старті та
  файл PID.
* Прибирання на старті зупиняє лише процеси, записані IDE. Якщо файл PID
  видалено вручну, «сирота» лишиться — тоді допоможе ручна кнопка (вона
  дивить��я лише на облік) або перезавантаження.
* Резервування VRAM під час роботи (коли модель простоює) регулюється
  політикою простою: `engine.unload_when_idle`, `engine.idle_unload_seconds`.
