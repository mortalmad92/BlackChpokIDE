# MCP: фактичний стан і супервізор

Дата: 2026-11-09.

---

## 1. Що вже працює (перевірено запуском)

```
CONFIG PATHS: [WindowsPath('C:/AI/blackchpock_ai/.cursor/mcp.json')]
SERVERS: ['blackchpok-ai']
STATUS: {"blackchpok-ai": "працює"}
TOOLS: 1 ['master_agent_router']
```

Транспорт, `initialize` handshake і реєстрація інструментів працюють.
MCP-сервер запускається **автоматично** через 400 мс після старту вікна,
без дій користувача.

---

## 2. Ланцюг «модель → інструмент → результат»

```
agent.tool_schemas()                      agent.py
  ├─ 37 вбудованих схем
  ├─ пам'ять NEUROMESH
  ├─ скіли
  └─ mcp_manager.tool_schemas()           ← MCP
       └─ _router_schemas()               ← прямі дії роутера
```

Далі `_fit_schemas()` лишає стільки схем, скільки вміщається у 40% вікна
контексту. Відповіді повертаються через `call_tool()` → `tool_orchestrator`.

**Перевірено наживо:** модель обрала `find_files`, інструмент виконався,
повернув 100 реальних шляхів, модель відповіла фактом.

---

## 3. Пастка, яку треба знати

`.cursor/mcp.json` у цьому проєкті містить:

```json
"MCP_LLM_BACKEND": "lmstudio",
"MCP_LMSTUDIO_URL": "http://127.0.0.1:1235/v1",
"MCP_LMSTUDIO_MODEL": "ministral-3-14b-reasoning"
```

Це **не** адреса поточного рушія (той працює на `8080` з ключем `local`).
Сервер стартує й повідомляє «працює», бо `initialize` не залежить від LLM.
Але будь-який інструмент, що всередині звертається до LLM або до embeddings,
отримає помилку з'єднання.

**Урок:** статус «працює» в MCP означає лише «процес піднявся й відповів на
handshake». Він НЕ означає, що функції сервера справні.

## 4. Налаштування

`McpSettings` (`config.py`):

```python
enabled: bool = True
auto_load_workspace: bool = True
servers: list[str] = []      # імена ВИМКНЕНИХ серверів
```

Логіка «усе, що у файлі, запускається, крім перелічених» зручна, але означає,
що будь-який `.mcp.json` у робочій теці виконує команди без окремого
підтвердження. Файли, які читаються: `.mcp.json`, `.cursor/mcp.json`,
`mcp.json`, `.vscode/mcp.json`.

**Рекомендація:** показувати в панелі джерело конфіга й команду, що
запускається, — щоб користувач бачив, що саме виконується від його імені.

## 5. Стан вимог (оновлено 2026-11-10)

| Вимога | Стан |
|---|---|
| health check після `initialize` | **є**: `McpManager.health_check()` питає `tools/list` і перевіряє придатність кожної схеми (`mcp_supervisor.schema_is_usable`) |
| ретрай старту з бекофом | **є**: `mcp_supervisor.BACKOFF = (1.0, 2.0, 4.0)`, до 3 спроб |
| watchdog (виявлення смерті процесу) | **є**: `McpManager.start_watchdog()`, перевірка раз на 5 с |
| restart policy | **є**: мертвий сервер перезапускається з наростанням бекофу; успіх скидає лічильник |
| graceful shutdown із очікуванням | **є**: `stop_all(timeout=5.0)` повертає `{ім'я: чи зупинився}` |
| прогрів інструмента end-to-end | немає: інструмент не викликається «нарозминку» після старту |

Не блокування інших серверів через помилку одного — **реалізовано**
(`start_all` збирає статуси й не кидає виняток далі).

**Чому health-check принциповий.** §3 цього документа описує пастку: сервер
відповідає на `initialize`, але його інструменти несправні, бо LLM-бекенд
вказано на мертвий порт. Статус «працює» цього не показував. Тепер
`health_check()` не вірить статусу: сервер із 3 схемами без імені
вважається **нездоровим**.

Доведено: `tests/test_mcp_supervisor.py` — 20 тестів, зокрема
`handshake_ok_but_broken_schemas_is_unhealthy`,
`retries_with_backoff_then_gives_up` (затримки рівно `[1.0, 2.0]`),
`watchdog_restarts_dead_server`, `stop_all_reports_server_that_hangs`.
Наживо на справжньому `server.py`: `health ok=True, tools=1`,
`stop_all: {'real': True}`.

## 6. Як додати власний сервер

1. Створити `.mcp.json` у корені робочої теки:

```json
{
  "mcpServers": {
    "my-server": {
      "command": "node",
      "args": ["server.js"],
      "cwd": "C:\\path\\to\\server"
    }
  }
}
```

2. Перезапустити IDE (або натиснути «Перезапустити MCP» у панелі).
3. Інструменти з'являться з префіксом `mcp__my-server__<назва>`.

---

## 7. Діагностика

* Статус кожного сервера — у панелі MCP.
* Причина відмови — у статусі рядка (`не запустився: …`).
* Повний лог — `userdata/ide.log`, категорія `blackchpok.mcp`.
