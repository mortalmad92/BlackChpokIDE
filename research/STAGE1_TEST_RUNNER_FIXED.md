## 2. Що зроблено

### 2.1. `tests/run_all.py`

* Видалено **другу** `main()` (колишні рядки 185–389). Лишилась одна —
  та, що будує список модулів з диска.
* `_SCRIPTS` замінено на наявну `script_modules()`, яка визначає скрипти
  **з коду** (`_module_has_main`), а не з ручного списку.
* Додано пояснення в докстрінг: чому дефект існував і що саме виправлено.

### 2.2. `unittest`-обгортки (22 файли)

До кожного скрипт-тесту додано компактний блок:

```python
class _ScriptSuite(unittest.TestCase):
    def test_script_passes(self) -> None:
        code = main()
        self.assertEqual(code, 0, f"main() повернув {code}")
```

Це **не переписування** тестів: `main()` лишається як був, запуск
`python tests/test_x.py` поводиться як раніше. Обгортка лише робить файл
видимим для `discover` і перетворює ненульовий код повернення на падіння
тесту.

Обгорнуто: `test_agent_e2e`, `test_all_tools`, `test_ast_editor`,
`test_cases_panel`, `test_chat_store`, `test_cloud_social`, `test_commands`,
`test_context_stats`, `test_deploy`, `test_edge_cases`, `test_layout_persist`,
`test_markdown_view`, `test_mcp_client`, `test_model_menu`, `test_rag_ui`,
`test_shell`, `test_streaming`, `test_tool_router`, `test_tools_panel`,
`test_voice_hub`, `test_web_preview`, `test_work_log`.

Не обгорнуто 13 «живих» модулів (потребують вікна або справжньої моделі) —
вони й далі йдуть окремим прогоном у `run_all.py`.

### 2.4. Два справжні дефекти в продукті

**`blackchpok_ide/tool_lazy.py:389` — скіли зникали зі схем.**
`_tier_of` перевіряв `_priority` **раніше** за список зовнішніх назв.
`agent.SCHEMA_PRIORITY` містить `list_skills` і `read_skill`, тому вони
діставали рівень «проєкт». А `eager_schemas` додає лише `TIER_EXTERNAL` —
тобто при лінивості скіли **тихо зникали** з того, що бачить модель.
Тест `test_features` ловив це як «агент бачить інструменти скілів —
15 інструментів». Виправлено: перевірку перенесено **до** `_priority`.

**`blackchpok_ide/main_window.py:1938` — розкладка не відновлювалась.**
`_do_apply_sash` при `total <= 0` (вікно ще без геометрії) просто виходив.
Саші лишались на 0, і збережена розкладка не застосовувалась. Під
навантаженням повного набору перший кадр запізнюється — `test_layout_persist`
падав з «було (620, 480), стало (0, 480)».

Виправлено двома частинами:

1. `update_idletasks()` перед виміром + до 4 повторів із наростанням паузи
   (`_schedule_sash_retry`), бо від'ємність/нуль саша — це стан «Tk ще не
   розклав панелі», а не «користувач так хотів».
2. **Головне:** `_verify_sash_applied` — після розстановки читаємо фактичні
   позиції. `PanedWindow.sashpos(i, N)` не гарантує негайного результату:
   якщо Tk не завершив розкладку, значення приймається й тут-таки
   скидається у від'ємне (`-2`). Без цієї перевірки код «ставив 620» і
   вважав роботу виконаною, хоч на екрані було 0.

Саме пункт 2 зробив поведінку стабільною: 3 прогони на чистому
`BLACKCHPOK_HOME` — усі зелені.

### Важливе застереження про вимірювання

`python -m unittest discover *> file` у цьому проєкті **губить підсумковий
рядок** `Ran N tests`: `setup_logging()` перехоплює потоки, і
`TextTestRunner` пише в уже закритий/перепідключений `stderr`. Тому
перевіряти треба або без redirection, або через власний
`TextTestRunner(stream=open(..., "w"))` — саме так зроблено вище. Інакше
виглядає, ніби прогін «обірвався», хоча він завершився коректно.
